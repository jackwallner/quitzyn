# Quit Zyn App Store metadata pass

Date: 2026-10-28

## First-pass history

The following research and decisions record the original pass, not the current keyword fields. See the independent review below for the final dispositions and evidence limitations. Positions and autocomplete results are the original author’s observations, not independently verified results.

## Scope and prior decisions

The nine main locales are en-US, de-DE, en-GB, sv, cs, fi, ru, da, and nl-NL. Supplemental keyword-only targets are en-CA, en-AU, and fr-CA for their storefronts, plus ar-SA and es-MX for U.S. indexing. The other U.S.-indexed fields were reviewed and retained because they carry the app's native-language terms. In-app localization is landing in parallel for de, ru, cs, sv, fi, nl, da, and other languages listed in the project brief. I also checked the remaining in-app localization descriptions present in Fastlane; none says the app is English-only. Since `docs/index.html` exists, this research lives under `project-docs/aso/` and is indexed in both relevant README files.

The only file named `aso-plan.md` is explicitly for Sober Tracker, App Store ID 6768869215, so it does not apply to Quit Zyn. Current Fastlane values and the dated en-US swap history are the starting point. The older Astro-derived `locale_aso_spec.py` has stale field values, including the en-US subtitle, so live SERPs decide whether any of those old proposals still apply. The current en-US title and subtitle stay because they support `zyn tracker` #8, `snus tracker` #10, and both `quit zyn` queries at #3.

The documented apply input is `scripts/aso_native_metadata.py`. This pass synchronizes the selected locale entries there, and `scripts/aso-apply-locale-optimizations.py` now supports a selected locale list. Keyword cleanup removes exact name and subtitle tokens while preserving distinct inflections Apple can index separately.

## Demand and rank method

Autocomplete was queried with the supplied Apple Search Hints method. Successful exact or app-seeded terms are listed by locale below. Apple iTunes Search API queries used the requested storefront, software entity, and a 200-result limit. Ranks are positions in that ordered response for track ID 6784788496. Ratings and release dates refer to the top ten returned apps.

The 90-day customer counts in the run brief were US 104, UK 22, Germany 15, Russia 11, Sweden 8, Czechia 8, Finland 7, Netherlands 7, Denmark 6, and Canada 5. Sweden returned $37 from 8 customers. I used those counts as market context, not as search-volume evidence.

Apple's current localization table lists the US additional display localizations: Mexican Spanish, Arabic, Russian, Simplified Chinese, French, Korean, Brazilian Portuguese, Vietnamese, and Traditional Chinese. See [Apple's App Store localization table](https://developer.apple.com/help/app-store-connect/reference/app-information/app-store-localizations). I preserved the other indexed language fields where they already carry market-specific terms or duplicate English coverage, and used the Arabic Saudi field for the US additions recorded below.

## Risks and maintenance

Apple Search API returned HTTP 429/403 on early attempts for `rogue`; a later successful retry confirmed no app position. Batch 6 completed after the cooldown with no errors. Rank claims use successful live responses only. Keyword removals were checked in the relevant storefront, and all fields stay within the 30 percent change guideline. No title or subtitle changed, which protects the measured top-ten phrases; the Czech natural-language title correction was deliberately rejected because the current title ranks #1 and #4.

The repo's older Astro-derived locale spec and generator contain stale field values, including a stale en-US subtitle. The apply input `scripts/aso_native_metadata.py` is synchronized to the final Fastlane fields for these 14 locales. Re-run the validator after using any legacy title/keyword generator, because its data is not the evidence used in this pass.

The locale-scoped apply command is `python3 scripts/aso-apply-locale-optimizations.py <locale> ...`. The required validator is `python3 scripts/validate-asc-metadata.py`; it checks name/subtitle, keyword, promotional text, description, repeated tokens, token overlap, prices, em dashes, and whitespace.
